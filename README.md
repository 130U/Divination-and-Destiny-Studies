# Divination and Destiny Studies

一个本地运行的八字校盘与背景分析 MVP：填写出生资料后，用固定版本的真一本地历法生成全部候选，再由 DeepSeek 建议暂用工作盘并展开分析。背景问卷全部可选；提供经历时用于候选比较和背景分析，留空时先给基于命盘的条件性分析。

## 当前能做什么

1. 填写必需的出生资料。27 道背景问题和 2 道适用性确认均可留空；缺失回答记为 `unknown`，不推测个人经历。
2. 支持公历、农历及闰月，准确分钟、同日时间范围或全天未知，IANA 时区和可选真太阳时。产品出生日期范围为转换后的公历 **1900-01-01 至评估当天**。
3. 本地逐分钟计算并保留所有符合输入的不同四柱候选，仅合并四柱完全相同的分钟，不用弱命理线索预先淘汰候选。
4. 第一次 AI 请求比较全部候选，列出已有支持、反证及未决事项。单候选直接成为暂定工作盘；多候选在材料不足时仍给暂定选择，并明确把握度有限。
5. 第二次 AI 请求针对工作盘展开实质分析；有背景时结合家庭、教育、职业和现实约束，没有背景时说明哪些判断只来自命盘。模型不重新换盘。

正常完成校盘和一次深入分析需要 **两次模型请求**，背景全部留空也可继续。同一有效会话中的成功校盘结果，以及同一工作盘的成功分析结果会缓存；重复相同操作不再请求模型。改选另一个工作盘、新建会话或明确重试失败请求可能产生新的费用。

报告用 `chart_only` / `context_supported` 区分是否有已知个人材料，用 `reportWarnings` 展示限制。轻微引用格式问题会保留正文并警告；候选身份错误或缺少必要正文仍会失败，已取得的该次模型用量会随错误保留。系统不自动发起付费重试。

模型建议是待核对的工作假设，不是经过校准的出生时辰概率。用户提供的经历不算模型独立预测命中；当前版本不提供定时辰正确率或未来预测准确率结论。

## 本地启动

需要 Node.js **24.12.0 或更新的 24.x 版本**和 npm。没有应用运行时 npm 依赖，开发检查依赖由锁文件固定。

```sh
npm ci
npm start
```

打开 [本地页面](http://127.0.0.1:3210)。服务只监听 `127.0.0.1`。未配置 DeepSeek 时仍可填写问卷和生成本地候选；页面禁用 AI 操作，直接请求 AI 接口也会明确报错，不会返回模拟结果。

将 `.env.example` 复制为本地 `.env`，用编辑器填写服务端配置，再重启服务。也可直接使用进程环境变量。`.env` 已被 Git 忽略，密钥不放进浏览器、请求表单或仓库。

**公开源码不会让克隆者使用作者的额度。** 每个克隆后自行运行的人需要配置自己的 API key，费用记在该 key 所属账户。若将自己的后端开放给别人访问，他们触发的请求会使用该后端运营者的 key；当前版本是本机单用户工具，没有网页访客各自填写 key 的功能，也没有多人账户隔离。

| 环境变量 | 用途 | 项目默认值 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 仅服务端读取的 API 凭据 | 未配置 |
| `DEEPSEEK_MODEL` | DeepSeek 模型名 | `deepseek-flash` |
| `DEEPSEEK_THINKING` | `low`、`medium`、`high`、`max` 或 `disabled` | `medium` |
| `PORT` | 本地监听端口 | `3210` |

默认使用 `deepseek-flash` + `medium`。截至 2026-10-28，[官方模型说明](https://api-docs.deepseek.com/)将该模型名对应到 **DeepSeek-V4.1-Flash-1017**；这是服务商可更新的别名，不是永久锁定的版本。客户端原样发送 `reasoning_effort: "medium"`，[官方映射](https://api-docs.deepseek.com/guides/thinking_mode/)将其实际思考强度解释为 `high`，不会由本项目降为 `low`。

服务端固定请求 DeepSeek 的 Chat Completions 接口，不允许表单指定任意服务地址。正常流程仍为两次请求，每次业务输出上限保持 8,192 tokens；思考强度调整不会自动扩大预算。模型可用性和费用由实际服务端响应及服务商计费决定。

## 检查与真实 API 验收

```sh
npm run check
```

执行 TypeScript 检查、合成数据测试及 vendor 完整性校验。2026-10-28 的 **0.2.0 验收中，90 项离线测试全部通过**。安装依赖后，这些检查不请求外部模型、不产生模型费用；HTTP 测试需要允许本机 loopback 连接。测试中的受控假客户端只验证工程行为，生产流程没有 mock 回退。

```sh
npm run test:live
```

这是独立、主动执行的真实 API 验收，使用仓库内的纯合成资料。成功路径发起 **两次付费请求**，检查候选比较、分析和两个阶段的缓存，并输出提供方用量；脚本在请求前限制单次运行最多两次尝试。未配置时输出 `LIVE_NOT_RUN` 并退出，失败时不自动重试，也可能已发生费用。

脚本另支持 `--birth-only`（不提供背景回答）和 `--single-candidate`（准确出生分钟的单候选资料），例如 `npm run test:live -- --birth-only --single-candidate`；仍限制最多两次请求。下述 0.2.0 真实验收通过浏览器完成，不表示这个 CLI 参数组合已经另行发起真实请求。

**0.2.0 浏览器验收（2026-10-28）：** 使用纯合成出生资料，27 题全部留空，单候选进入暂定工作盘，两阶段真实 DeepSeek 请求均成功，输出 4 节分析。review 为 4,656 tokens / 6,852 ms，analysis 为 11,053 tokens / 39,336 ms，两次合计 15,709 tokens。默认模型和思考配置为 `deepseek-flash` + `medium`。

**0.1.0 历史样例：** 首轮曾在 analysis 引用校验失败且未保留用量；第二轮两次请求通过，共 24,353 tokens，3 个候选的 review 为 `insufficient_evidence`，脚本明确选择一个合成候选继续分析，缓存重复未新增请求。这是另一轮历史验收，不能与 0.2.0 用量混算。两轮都只验证接口与流程，**不是校盘成功或预测准确率验证**；返回模型标签也不能独立证明实际使用了 1017 快照。完整结果见 [验证记录](docs/VALIDATION.md)。

页面和导出中的 `usage` 仅描述对应的那一次模型调用，不包含另一阶段、此前失败或重试，也不是账户累计账单。缓存展示的是原调用用量，不代表再次计费。

## 数据与边界

服务端会话只存在进程内存中，从创建起 30 分钟过期并清理；重启或手动清除也会丢失。模型请求只在明确触发 AI 操作时发出：校盘发送出生资料、候选盘和校盘回答，分析再加入背景回答。清除本地会话不能撤回已经发送给服务商的请求。

候选生成采用一分钟精度及明确的年/月、日/时分离时钟规则。相同四柱合并后的起运与大运只使用代表分钟，不能当成整组分钟共享的精确交运时刻。没有集成完整真一盲派判盘引擎、其他术数、账号或付费系统。

本仓库可独立运行，不依赖旧 `bazi-context-agent` 工作区，也不会读取或修改旧仓库。保留的问卷设计来源与代码许可见下列文档。
